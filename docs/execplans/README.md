# ExecPlans

Design documents for work that spans more than one session. One file per piece of work, named
`YYYY-MM-DD-kebab-case-summary.md`, committed on the branch that does the work.

A plan is the durable record of a change: why it was worth doing, what was decided and why, what
went wrong on the way, and how to verify the result. Someone with only the working tree and one of
these files should be able to finish the work.

The specification for writing one, plus its ensemble-specific addendum, is
`.claude/skills/execplans/references/PLANS.md`. `AGENTS.md` says when to reach for a plan.

Finished plans stay. A plan with a filled-in `Outcomes & Retrospective` is the closest thing this
repo has to a design history.
